# AstrBot Life Scheduler Plugin

> **缓存优化 fork · v2.8.0-cache.1**
>
> 基于木有知的原版维护，保留原作者署名。固定规则留在系统提示词，动态状态通过本轮临时内容注入，
> 减少活动、穿搭和衣柜变化对前缀缓存的影响。安装及后续更新地址：
> [Shennoter/astrbot_plugin_life_scheduler](https://github.com/Shennoter/astrbot_plugin_life_scheduler)。

为 AstrBot 设计的拟人化生活日程插件。利用 LLM 根据日期、节日、历史日程和近期对话，自动生成每日穿搭和日程安排，并注入模型上下文，让 Bot 拥有连续的"生活"状态。

## 功能特性

- **日程生成**: 结合日期、节日、历史日程和近期对话，生成拟人化日程
- **衣柜穿搭**: 从可编辑衣柜中选取一套作为今日穿搭基准
- **缓存友好的状态注入**: 固定规则追加到 System Prompt，当日状态与衣柜列表默认作为本轮临时内容注入
- **当前状态提取**: 对含时间点的日程自动提取当前或最近活动，减少对话中说出与日程冲突的状态
- **懒加载**: 未到生成时间时，首次对话自动触发生成
- **补充要求**: 重写日程时可附加自定义要求，让生成更符合预期
- **图片穿搭**: `重写日程` 支持直接图片或引用图片，先转写穿搭再生成日程
- **衣柜方案**: 支持将文字、图片或混合消息整理为持久化的备选穿搭方案
- **固定编号**: 新穿搭追加到衣柜末尾，不会因新增方案改变现有 `穿搭N` 编号
- **穿搭展示图**: 管理员可用 `展示 穿搭N` 绑定图片，重复绑定会覆盖旧图，查看衣柜时与方案一起展示
- **面板维护**: 衣柜是 AstrBot 插件配置项，可在 WebUI 直接增删、修改和调整顺序
- **对话维护**: 管理员可让 Bot 在自然对话中新增、删除、修改衣柜方案或今日计划

## 安装

```bash
pip install holidays APScheduler
```

## 指令列表

| 指令 | 权限 | 说明 |
| :--- | :--- | :--- |
| `查看日程` | 所有人 | 查看今日日程和穿搭 |
| `重写日程` | 管理员 | 重新生成今日日程 |
| `重写日程 <补充要求>` | 管理员 | 带补充要求重新生成，例如：`重写日程 今天穿黑色连衣裙，安排一个下午茶` |
| `重写日程 <图片或补充要求>` | 管理员 | 直接发送图片，或引用图片后发送指令；图片会作为今日穿搭参考 |
| `重写日程 穿搭N` | 管理员 | 按 `查看衣柜` 图片中的数字编号选择一套穿搭，例如 `重写日程 穿搭2` |
| `放进衣柜 <文字>` | 管理员 | 可附图片、引用图片或文字，整理后保存为衣柜方案 |
| `查看衣柜` | 所有人 | 以 HTML 图片展示最近保存的穿搭方案及数字编号 |
| `展示 穿搭N` | 管理员 | 发送或引用图片，为指定衣柜方案绑定展示图；再次绑定会覆盖旧图 |
| `日程时间 <HH:MM>` | 管理员 | 设置每日自动生成时间 |
| `参考会话 [set\|show\|clear]` | 管理员 | 设置、查看或清除定时生成日程时参考的默认会话 |

别名：`life show`、`life renew`、`life time`、`life umo`

## 配置项

| 字段 | 类型 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- |
| `inject_as_temp` | bool | `true` | 开启后固定规则留在系统提示词，动态日程和衣柜列表作为本轮临时内容注入，不写入历史。关闭或旧版缺少临时内容 API 时使用系统提示词注入，并记录兼容提示 |
| `schedule_time` | string | `07:00` | 每日自动生成日程的时间 |
| `reference_history_days` | int | `3` | 生成时参考的历史日程天数 (1-7) |
| `reference_recent_count` | int | `10` | 生成时参考的近期会话数量，0 表示不参考 |
| `default_reference_umo` | string | `""` | 默认参考会话来源，用于定时生成日程或未指定会话来源时兜底参考 |
| `llm_provider` | provider | 空 | 日程生成模型，留空跟随当前 provider |
| `image_provider` | provider | 空 | 图片转写模型，留空跟随 `llm_provider`；建议选择支持视觉输入的 provider |
| `wardrobe` | template_list | `[]` | 衣柜穿搭方案，列表顺序对应 `穿搭1`、`穿搭2`...，每项带隐藏稳定 ID |
| `pool` | object | - | 今日主题、心情色彩和日程类型创意池 |
| `prompt_template` | text | - | LLM 生成日程的 Prompt 模板 |

### 创意池 (pool)

每次生成日程时，从以下创意池随机选取一项融入提示词：

| 池 | 示例 |
| :--- | :--- |
| `daily_themes` | 探索日、社交日、宅家日、工作日、运动日... |
| `mood_colors` | 慵懒、活力、优雅、俏皮、温柔、冷艳... |
| `schedule_types` | 户外活动型、社交聚会型、独处充电型、随性漫游型... |

旧版 `pool.outfit_styles` 会在首次启动时自动转为衣柜兼容项，迁移后不再参与日程生成。

### Prompt 模板占位符

| 占位符 | 说明 |
| :--- | :--- |
| `{date_str}` | 日期，如 2026年01月22日 |
| `{weekday}` | 星期几 |
| `{holiday}` | 节日信息（中国节日） |
| `{persona_desc}` | Bot 人设描述 |
| `{daily_theme}` | 从创意池选取的今日主题 |
| `{mood_color}` | 从创意池选取的心情色彩 |
| `{outfit_style}` | 从今日选定衣柜方案中提取的简短风格标签 |
| `{outfit_plan}` | 今日选定的完整衣柜穿搭方案 |
| `{schedule_type}` | 从创意池选取的日程类型 |
| `{history_schedules}` | 历史日程记录 |
| `{recent_chats}` | 近期对话记录 |
| `{r1}`、`{r2}` … `{rN}` | 每次生成时独立随机的 1-100 整数 |

## 注入机制

插件在 LLM 请求时自动注入当前状态：

```xml
<character_state>
时间: 下午
当前状态: 14:00 在咖啡厅看书...
穿着: 白色针织衫搭配米色阔腿裤...
今日日程: 上午整理房间，下午去咖啡厅看书...
</character_state>
```

默认将上面的状态及衣柜列表放进 `extra_user_content_parts`，通过 `TextPart.mark_as_temp()`
标记为本轮临时内容。状态遵循规则、衣柜工具使用规则放在系统提示词中；动态状态变化时，这些固定规则保持一致。
衣柜列表只是供本轮参考的快照，修改、删除前仍需调用衣柜工具获取最新数据。

已有配置如果明确保存了 `inject_as_temp=false`，升级后仍会保留该值；请在插件配置中打开
“缓存优化：将动态日程作为临时内容注入”。缺少临时内容 API 的旧版 AstrBot 会使用系统提示词兼容模式。

配合群聊增强的主动聊天时，请使用
[群聊增强缓存 fork](https://github.com/Shennoter/astrbot_plugin_group_chat_plus)
`V1.2.3.hotfix.2-cache.2` 或后续版本，其群聊、私聊主动发言会转发临时内容。
普通 AstrBot 内置 AI 通过标准请求流程处理这些内容。

### 验证

回归测试覆盖临时注入、动态状态更新、固定规则去重、显式关闭、旧 SDK 兼容，以及原有日程和衣柜功能。
额外的 SDK 探针加载实际消息序列化代码，检查状态参与当前请求且保存历史时被移除，并可验证群聊增强的主动调用边界：

```sh
python -m pytest -q tests
python tests/probe_prompt_cache.py /path/to/AstrBot --group-chat-plus /path/to/group-chat-plus-fork
```

测试不调用模型或发送消息。实际命中率取决于模型、中转、请求间隔与历史裁剪方式，需上线后比较未缓存输入量和费用。

### 自然语言维护

管理员在普通对话中可以直接说“这套不好看，删掉”“穿这套时不要穿鞋”“那件衣服好看，放进衣柜”，主 Agent 会按意图调用衣柜或今日计划工具。衣柜工具会再次经过结构化转写，只保存穿搭、配饰、发型、妆容和造型细节，不保存场景、动作、日程、天气或镜头描述。

## 外部插件调用

插件提供 `get_life_context()` 公共方法，供生图、每日分享等外部插件读取当前全局日程：

```python
life_data = await life_scheduler_plugin.get_life_context()
```

返回数据包含 `outfit`、`schedule`、`meta.style` 和 `timeline`。本插件当前保持全局日程语义，不按人格或会话隔离。

## 注意事项

1. 每日生成消耗 LLM Token，参考天数和对话数越多消耗越大
2. 需安装 `holidays` 库才能识别中国节日
3. 重写日程会覆盖当日已有数据
